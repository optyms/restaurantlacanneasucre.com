<task type="auto">
  <name>Task 2: Creer les bases D1, appliquer le schema, creer la branche staging</name>
  <files>wrangler.jsonc, migrations/0001_create_reservations.sql</files>
  <action>
1. Creer le fichier de migration migrations/0001_create_reservations.sql :
   ```sql
   -- Schema de la table reservations pour le systeme de reservation La Canne a Sucre
   CREATE TABLE IF NOT EXISTS reservations (
     id          TEXT    PRIMARY KEY,
     first_name  TEXT    NOT NULL,
     last_name   TEXT    NOT NULL,
     phone       TEXT    NOT NULL,
     email       TEXT    NOT NULL,
     date        TEXT    NOT NULL,
     time_slot   TEXT    NOT NULL,
     party_size  INTEGER NOT NULL,
     created_at  TEXT    NOT NULL DEFAULT (datetime('now'))
   );
   ```

2. Creer les deux bases D1 via Wrangler CLI :
   ```bash
   npx wrangler d1 create reservations_prod
   npx wrangler d1 create reservations_staging
   ```
   Capturer les `database_id` retournes par chaque commande.

3. Mettre a jour wrangler.jsonc : remplacer les placeholders `<PROD_DB_ID>` et `<STAGING_DB_ID>` par les vrais database_id retournes a l'etape 2.
   - Top-level `d1_databases[0].database_id` → STAGING_DB_ID
   - `env.production.d1_databases[0].database_id` → PROD_DB_ID
   - `env.preview.d1_databases[0].database_id` → STAGING_DB_ID

4. Appliquer le schema aux deux bases :
   ```bash
   npx wrangler d1 migrations apply reservations_staging --remote
   npx wrangler d1 migrations apply reservations_prod --remote
   ```
   NOTE : Utiliser `--remote` pour appliquer sur les bases Cloudflare (pas en local).

5. Creer la branche staging et la pousser sur GitHub :
   ```bash
   git checkout -b staging
   git push -u origin staging
   git checkout main
   ```
   Sur Cloudflare Pages, la branche `staging` sera automatiquement deployee en preview (utilise `env.preview` dans wrangler.jsonc).

  <action>
L'infrastructure D1 et la configuration Wrangler sont en place. Il faut maintenant configurer les 4 secrets Twilio pour le projet Pages.

IMPORTANT — Avant de configurer les secrets, verifier le type de sender Twilio :
1. Aller sur Twilio Console → Phone Numbers → Active Numbers
2. Si le numero est un mobile francais (+336 ou +337) : les SMS A2P seront BLOQUES par les operateurs francais
   → Il faut enregistrer un Alphanumeric Sender ID (gratuit) sur https://help.twilio.com/articles/36973882933787
   → Utiliser cet Alphanumeric ID comme TWILIO_FROM_NUMBER
3. Si le numero est deja un Alphanumeric Sender ID ou un numero technique (+3393903xxx) : vous pouvez continuer

Configurer les secrets (executer dans le terminal, le CLI demandera la valeur de chaque secret) :
```bash
npx wrangler pages secret put TWILIO_ACCOUNT_SID --project-name restaurantlacanneasucre
npx wrangler pages secret put TWILIO_AUTH_TOKEN --project-name restaurantlacanneasucre
npx wrangler pages secret put TWILIO_FROM_NUMBER --project-name restaurantlacanneasucre
npx wrangler pages secret put TWILIO_OWNER_NUMBER --project-name restaurantlacanneasucre
```

NOTE : Le `--project-name` doit correspondre au nom exact du projet dans Cloudflare Dashboard → Workers and Pages.
Si le nom est different de "restaurantlacanneasucre", adapter la commande.

Aussi, remplir le fichier .dev.vars avec les vraies valeurs pour le dev local.
