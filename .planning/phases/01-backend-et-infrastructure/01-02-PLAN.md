  <action>
Creer `functions/api/reservations.ts` — un seul fichier qui gere tout le flux.

**Structure du fichier (dans cet ordre) :**

1. **Imports et types :**
   ```typescript
   import { z } from 'zod';
   ```
   Declarer l'interface `Env` avec les 5 bindings (DB, TWILIO_ACCOUNT_SID, TWILIO_AUTH_TOKEN, TWILIO_FROM_NUMBER, TWILIO_OWNER_NUMBER).

2. **Constantes :**
   - `VALID_TIME_SLOTS` : `['12:00', '12:30', '13:00', '13:30', '19:00', '19:30', '20:00', '20:30', '21:00']`
   - `FRENCH_PHONE_RE` : `/^(?:(?:\+33|0033)[67]|0[67])\d{8}$/` — numeros francais metropolitains uniquement (06, 07, +33)
   - `RESTAURANT_PHONE` : `'04 66 51 84 15 61'` — ATTENTION verifier le vrai numero dans l'index.html du site (section contact/footer, actuellement +33 6 51 84 15 61) et le formater pour le SMS. Utiliser le numero du site.

3. **Schema Zod :**
   ```typescript
   const reservationSchema = z.object({
     first_name:  z.string().min(1).max(100),
     last_name:   z.string().min(1).max(100),
     phone:       z.string().regex(FRENCH_PHONE_RE, 'Numero de telephone francais metropolitain requis (06, 07, +33)'),
     email:       z.string().email('Adresse email invalide'),
     date:        z.string().regex(/^\d{4}-\d{2}-\d{2}$/, 'Format de date YYYY-MM-DD requis'),
     time_slot:   z.enum(VALID_TIME_SLOTS),
     party_size:  z.number().int().min(1).max(20),
     honeypot:    z.string().max(0).optional(),
   });
   ```

4. **Handler principal `onRequestPost` :**
   Flux exact :
   a. Parser le body JSON (try/catch → 400 si invalide)
   b. Valider avec `reservationSchema.safeParse(body)` → 400 avec `parsed.error.flatten()` si invalide
   c. Verifier honeypot : si `data.honeypot` est non-vide → 400 "Spam detecte"
   d. Regles metier :
      - Date dans le passe : comparer `data.date < new Date().toISOString().slice(0, 10)` → 400 "La date ne peut pas etre dans le passe"
      - Lundi : `new Date(data.date + 'T12:00:00Z').getUTCDay() === 1` → 400 "Le restaurant est ferme le lundi"
      ATTENTION au pitfall timezone : utiliser la comparaison de strings pour les dates, et `T12:00:00Z` + `getUTCDay()` pour le jour de la semaine.
   e. Generer l'ID : `crypto.randomUUID()` (built-in Workers, pas de dependance)
   f. Inserer dans D1 avec `env.DB.prepare().bind().run()` — try/catch → 500 si echec
   g. Envoyer les deux SMS en parallele avec `Promise.allSettled()` — APRES le D1 insert (reservation deja sauvee)
   h. Construire la reponse :
      - Status 201
      - Body : `{ id, message: "Reservation enregistree avec succes" }`
      - Si un ou les deux SMS echouent : ajouter `warnings: ["SMS client echoue", "SMS proprietaire echoue"]` au body
      - Logger les echecs SMS avec `console.error()` (visible dans Workers logs)

5. **Fonction `sendSms(env, to, body)` :**
   - POST vers `https://api.twilio.com/2010-04-01/Accounts/${env.TWILIO_ACCOUNT_SID}/Messages.json`
   - Header `Authorization: Basic ${btoa(env.TWILIO_ACCOUNT_SID + ':' + env.TWILIO_AUTH_TOKEN)}`
   - Header `Content-Type: application/x-www-form-urlencoded`
   - Body : `new URLSearchParams({ To: to, From: env.TWILIO_FROM_NUMBER, Body: body }).toString()`
   - Si `!res.ok` → throw Error avec le message Twilio
   - NE PAS utiliser le SDK Twilio (incompatible avec Workers runtime)

6. **Templates SMS — GSM-7 SAFE :**
   IMPORTANT : Utiliser uniquement des caracteres GSM-7. Les caracteres `e, è, é, à, ù` sont OK. Les caracteres `ê, ë, î, ï, ô, û, oe` declenchent UCS-2 (70 chars/segment au lieu de 160).

   SMS client (< 160 chars) :
   ```
   La Canne a Sucre - Reservation confirmee
   {first_name} {last_name}, {party_size} pers.
   Le {date} a {time_slot} (service {midi|soir})
   Pour annuler : {RESTAURANT_PHONE}
   ```
   Determiner midi/soir : `time_slot <= '14:00'` → 'midi', sinon 'soir'.

   SMS proprietaire (< 160 chars) :
   ```
   Nouvelle resa #{id_short}
   {first_name} {last_name} - {party_size} pers.
   {date} {time_slot} ({midi|soir})
   Tel: {phone} | {email}
   ```
   Utiliser `id.slice(0, 8)` pour l'ID court.

7. **Fonction utilitaire `jsonResponse(body, status)` :**
   ```typescript
   function jsonResponse(body: unknown, status: number): Response {
     return new Response(JSON.stringify(body), {
       status,
       headers: { 'Content-Type': 'application/json' },
     });
   }
   ```

**Decisions de discretion appliquees :**
- Ton des SMS : Professionnel mais chaleureux (adapte restaurant)
- Encodage : GSM-7 (sans accents problematiques) pour rester a 160 chars/segment et minimiser les couts
- SMS proprietaire : Toutes les infos pertinentes (nom, party_size, date, creneau, tel, email)
- Pas de retry Twilio automatique : Twilio gere ses propres retries cote carrier. On log l'erreur et on avertit dans la reponse API
- Gestion SMS partiel : chaque SMS est independant dans Promise.allSettled, les warnings sont specifiques par SMS
- Logging : console.error (visible dans Workers logs, pas de colonne D1 supplementaire pour simplifier le schema)
- Party size : min 1, max 20 (raisonnable pour un restaurant)
- Reponse API succes : ID + message + warnings optionnels
- Erreurs de validation : par champ via Zod flatten + messages metier globaux pour les regles business
- ID de reservation : crypto.randomUUID() (built-in, pas de deps)
- Messages d'erreur API : en francais (coherent avec le SMS et le public cible)
